Architecture patterns

The attention you met in Stage 2 is powerful but expensive — it re-compares every token with every other, and the memory to do that grows with the conversation. The frontier trick of 2025–26 is to use it sparingly: cheap layers most of the time, real attention only now and then. This distinction — cheap most of the time, real attention only when it counts — is exactly what separates two of 2026's most-discussed open models.

Full attention

Every token can look up any earlier token exactly. Perfect recall — but it stores one memory slot per token (the KV cache) and cost grows with the square of the length.

Linear attention

Each token is folded into one fixed-size running state. Constant memory, cost grows only linearly — but recall is a lossy summary, not an exact lookup.

This is why hybrid models fit on modest hardware. With only a quarter of the layers holding a growing cache, a hybrid model's memory rises far more slowly with context. That's why a design like this can offer huge context windows on a single Mac or workstation GPU rather than a data-center rack. It's also a common sizing mistake: estimating a hybrid model's memory as if every layer were full attention overstates the real cost substantially.

One more Kimi trick: MLA. Even its full-attention layers shrink the cache further by compressing the stored keys and values into a small latent space instead of keeping them full-size — so the chart above would sit lower still for Kimi. Qwen keeps it simpler with grouped-query attention. Same goal — cheap memory — reached two different ways, which is the whole story of why two models with the same skeleton look so different.
