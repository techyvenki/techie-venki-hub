Compression

A trained model is enormous. Three techniques make it small and cheap enough to actually run — and each is a different trick: shrink every number (quantization), train a small model to copy a big one (distillation), or only switch on part of the model per token (mixture-of-experts).

A

Quantization — fewer bits per weight

A weight is just a number. Store it in fewer bits and the whole model shrinks. The cost is precision: with fewer bits, each weight snaps to a coarser grid. Change the precision and watch the grid — and the trade-offs — move. This is the 4-bit / 8-bit / bf16 choice you'll see on every open-weight model card.

Why fewer bits runs faster. Generating a token means reading every weight from memory. Local inference is limited by memory bandwidth, not math — so halving the bytes per weight roughly doubles the tokens per second. That's the counterintuitive part: 4-bit is both the smallest and the fastest, and nearly lossless. Below 4-bit, quality falls off a cliff.

B

Distillation — a big model teaches a small one

Train a small "student" to imitate a large "teacher" instead of learning from raw text alone. The student ends up far better than an identical model trained from scratch — this is the main reason a 27B model can rival something many times its size.

A hard label says only the right answer. A teacher hands over its whole probability distribution — including which wrong answers are almost right. That richer signal is what the student learns from. Toggle to compare.

Input: “The capital of France is ___”

The soft targets quietly teach geography: the student learns Lyon is a French city (plausible) while London is not (a different country) — a distinction a one-hot label can't convey. Modern small models are almost always distilled from a much larger sibling; it's the compression step that happens during training, not after.

C

Mixture-of-experts — only pay for what you use

Instead of one big network, use many small "expert" networks and a router that picks just a few per token. The model can be huge in total knowledge while only a fraction switches on for any given word. Drag the router and step through tokens.

This is Kimi K3, and why it isn't Qwen3.8. The real Kimi K3 has 2.8 trillion total parameters but activates only about 104 billion per token — 16 routed experts out of 896, plus 2 shared. It "knows" like a 2.8T model but "runs" like a 104B one. Qwen3.8-27B is dense — every parameter fires every token — which is why it's simpler and smaller. Same efficiency goal, two different answers.
