Serving & inference

Everything so far built the model. This is running it — where the weights, the KV cache, and the precision you chose collide into two practical questions: how fast does it generate, and will it even fit? This is exactly where a question like "will a 27B model run on my Mac?" gets answered.

A

Two phases: prefill, then decode

Generation isn't one uniform process. First the model reads your whole prompt at once (prefill), then it produces the answer one token at a time (decode). They have completely different speeds — and understanding why explains everything about performance.

Press Prefill to process the prompt.

Prefill

The whole prompt goes through in parallel — all tokens at once. It's compute-bound and fast per token, but it's the wait before the first word appears ("time to first token").

Decode

Each new token must read every weight from memory, one step at a time. It can't be parallelized across future tokens — so this is the slow part, and it's limited by memory bandwidth, not math.

B

Why precision decides speed

Because decode reads all the weights for every single token, tokens per second is roughly memory bandwidth ÷ model size. Fewer bits means a smaller model means more tokens per second — the counterintuitive result, turned into an actual formula.

Speculative decoding gets around the one-token-at-a-time wall: a small, fast draft proposes several tokens and the big model verifies them all in one pass, keeping the ones it agrees with. Qwen3.8's MTP heads do this without a separate draft model. Numbers here are theoretical peaks — real throughput is 50–70% of these — but the ratios are what matter: 4-bit beats 8-bit beats 16-bit, every time.

C

Will it run on my machine?

The whole series in one calculator. Total memory = weights + KV cache + overhead. Weights come from size and precision; the KV cache grows with context (Stage 6). Set it up and find out. Start with the defaults — a 27B, 4-bit, on 48 GB — then push the context and watch it break.

Context is a memory tax. A model trained for, say, 256K tokens can be stretched further (with tricks like YaRN) — but every extra token of context adds KV cache. That's why "the weights fit" isn't the same as "it runs": a long conversation can quietly blow past your RAM even when the model itself was comfortable. Hybrid architectures (Stage 6) soften this by keeping the cache small.

That's the whole pipeline.

Model cards throw around terms like "4-bit," "27B," "MoE," and "hybrid attention" as if they're self-explanatory. They rarely are — until you've built up the pieces yourself. Across these seven stages — tokens, parameters, pretraining, alignment, compression, architecture, and serving — you now have everything you need to read any model card end to end, and to know whether that model will actually run on your machine.
